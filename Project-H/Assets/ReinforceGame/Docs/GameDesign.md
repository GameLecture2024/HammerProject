# 강화 작업실 게임 기획서

## 게임의 핵심

플레이어는 출구 없는 작업실의 엔지니어다. 무료로 공급받은 장비를 망치로 강화하고 판매해 라운드 목표액을 채운다. 강화에는 비용과 횟수 제한이 없지만 장비는 하락하거나 파괴될 수 있다. 지금 팔아 목표를 확보할지, 한 번 더 강화할지, 좋은 장비를 다음 라운드에 남길지가 핵심 선택이다.

플레이어는 한자리에 서서 작업대와 좌우 거치대를 바라본다. 이동과 전투 없이 상품 선택, 강화, 판매, 보관에 집중하는 PC 마우스 중심의 1인칭 게임이다. 작업명은 **THE LAST FORGE**다.

이 기획서의 표와 수식은 현재 프로토타입의 기준값이다. 구조와 구현 절차는 [기술 설계서](TechnicalDesign.md)에 대응한다.

Unity에서 순서대로 제작하려면 [구현 실습 튜토리얼](ImplementationTutorial.md)을 함께 사용한다.

## 플레이 공간과 시점

| 구역 | 위치 | 기능 | 시각적 구분 |
| --- | --- | --- | --- |
| 공급 진열대 | 플레이어 왼쪽 | 라운드당 기본 상품 6개 제공 | 따뜻한 주황색 조명 |
| 강화 작업대 | 정면 | 상품 1개 배치와 강화 | 천장 작업등과 금속 강화판 |
| 회수 버튼 TAKE | 작업대 왼쪽 앞 | 작업대 상품을 왼손으로 회수 | 황동 버튼 |
| 판매 트레이 SELL | 작업대 오른쪽 | 손에 든 상품 판매 | 청록색 트레이 |
| 보관 거치대 | 플레이어 오른쪽 | 상품 6개까지 다음 라운드에 보존 | 차가운 청색 조명 |
| 라운드 버튼 NEXT ROUND | 정면 벽 | 목표 달성 후 다음 라운드 진입 | 청록색 벽면 스위치 |

작업실은 바닥, 천장, 네 벽으로 막힌 약 6m × 6m 공간이다. 문이나 창문, 외부 풍경은 없다. 전체는 어둡게 유지하되 작업대, 공급 상품, 보관 상품은 식별할 수 있어야 한다. 따뜻한 작업 영역과 차가운 보관 영역의 대비로 시선 이동을 유도한다.

엔지니어의 오른손에는 전용 강화 망치가 있다. 기본 게임 화면에는 오른손과 망치가 보이고, 상품을 들었을 때만 왼손과 상품이 추가된다. 머리, 몸통, 다리와 배낭은 게임 카메라에 나타나지 않는다. 편집용 씬에는 전신 모델과 리그를 유지한다.

## 기본 플레이 흐름

1. 새 게임은 1라운드, 판매액 0, 공급 상품 6개, 빈 보관대로 시작한다.
2. 왼쪽 진열대의 상품을 선택해 왼손에 든다.
3. 정면 작업대를 클릭해 상품을 내려놓는다.
4. 표시된 현재 가치와 성공·하락·파괴 확률을 확인한다.
5. 작업대 상품 또는 강화판을 클릭해 강화한다. 원하는 만큼 반복할 수 있다.
6. TAKE로 상품을 회수한다.
7. SELL에 팔아 판매액을 확보하거나 오른쪽 빈 보관 칸에 놓는다.
8. 목표를 달성하면 손과 작업대를 비운 뒤 NEXT ROUND를 누른다.
9. 보관 상품은 유지되고 공급 진열대는 기본 상품 6개로 다시 채워진다.

목표 달성은 즉시 라운드를 종료하지 않는다. 남은 공급품을 추가로 강화하거나 보관할 수 있다. 목표를 넘겨 판매한 금액은 다음 라운드에 이월되지 않으므로, 목표 달성 후에는 가치 있는 상품을 남기는 선택이 중요해진다.

## 조작

| 입력 | 상황 | 동작 |
| --- | --- | --- |
| 마우스 우클릭 드래그 | 모든 플레이 상태 | 좌우·상하 시점 회전 |
| 우클릭 해제 | 시점 회전 중 | 포인터를 표시하고 상품 선택 모드로 복귀 |
| 좌클릭 | 공급 또는 보관 상품, 빈 왼손 | 상품 집기 |
| 좌클릭 | 상품을 든 채 빈 작업대 | 상품 배치 |
| 좌클릭 | 작업대 상품 또는 강화판, 빈 왼손 | 강화 1회 |
| 좌클릭 | TAKE, 작업대에 상품이 있고 빈 왼손 | 작업대 상품 회수 |
| 좌클릭 | SELL, 왼손에 상품이 있음 | 즉시 판매 |
| 좌클릭 | 빈 보관 칸, 왼손에 상품이 있음 | 해당 칸에 보관 |
| 좌클릭 | NEXT ROUND, 목표 달성 및 손·작업대가 비어 있음 | 다음 라운드 |
| R | 모든 상품을 소진하고 목표액 미달 | 현재 라운드 재도전 |

시점 회전 중에는 선택 입력을 처리하지 않는다. 강화 연출이 진행되는 동안에는 집기, 배치, 판매, 재도전과 추가 강화 입력을 막는다. 작업대 상품을 직접 클릭하면 강화하므로 회수에는 TAKE를 사용한다.

## 상품 구성

모든 상품은 같은 강화 규칙을 사용한다. 상품 간 차이는 형태, 기본 판매가, 표시 크기와 부착 자세다. 방패와 렌치도 강화·판매할 수 있다.

| 상품 | 식별자와 프리팹 파일명 | 기본 판매가 | 표시 최대 길이 |
| --- | --- | ---: | ---: |
| 한손검 | `sword_1handed` | 35 | 0.62m |
| 한손도끼 | `axe_1handed` | 40 | 0.62m |
| 원형 방패 | `shield_round` | 32 | 0.62m |
| 지팡이 | `staff` | 50 | 0.80m |
| 단검 | `dagger` | 25 | 0.62m |
| 엔지니어 렌치 | `engineer_Wrench` | 38 | 0.62m |

공급 진열대는 위 순서대로 매 라운드 1개씩 제공한다. 무작위 상품 추첨은 없다. 상품은 +0으로 공급되며, 가져간 자리는 해당 라운드에 자동으로 다시 채워지지 않는다. 공급품을 진열대로 되돌리는 기능은 없다.

엔지니어는 KayKit의 `Engineer.prefab`, 강화 망치는 `UpgradeHammer.fbx`를 사용한다. 망치는 상품이 아니며 판매·강화·보관 대상에 포함되지 않는다.

## 강화 규칙

강화 대상은 작업대에 있는 상품 1개다. 1회 시도는 성공, 단계 하락, 파괴 중 하나로 끝난다. 강화 자체로 판매액이나 재화를 차감하지 않는다. 시도 횟수는 통계로만 표시한다.

| 시도 전 단계 | 성공 | 단계 하락 | 파괴 | 성공 후 단계 |
| --- | ---: | ---: | ---: | --- |
| +0 | 90% | 5% | 5% | +1 |
| +1 | 80% | 12% | 8% | +2 |
| +2 | 70% | 18% | 12% | +3 |
| +3 | 60% | 22% | 18% | +4 |
| +4 | 50% | 25% | 25% | +5 |
| +5 | 40% | 28% | 32% | +6 |
| +6 | 30% | 30% | 40% | +7 |
| +7 | 20% | 30% | 50% | +8 |
| +8 | 시도 불가 | 시도 불가 | 시도 불가 | 최대 단계 |

- 성공하면 현재 단계가 1 오른다.
- 하락하면 현재 단계가 1 내려간다. +0에서는 +0을 유지한다.
- 파괴되면 상품은 완전히 제거된다. 판매액, 파편, 보상은 지급하지 않는다.
- +8에서는 추가 시도를 처리하지 않고 최대 단계 안내를 표시한다.
- 확률은 매번 독립적이다. 누적 실패 보정, 천장과 연속 성공 보너스는 없다.

망치를 약 0.5초 동안 휘두른 후 결과를 확정한다. 결과 조명은 약 0.35초간 유지한다. 성공은 초록, 하락은 주황, 파괴는 빨강으로 표시하고 텍스트도 함께 제공한다. 색만으로 결과를 구별하게 하지 않는다.

## 가격과 판매

`판매가 = RoundToInt(상품 기본가 × 현재 단계의 가격 배율)`

| 단계 | 배율 | 한손검 판매가 |
| --- | ---: | ---: |
| +0 | 1.0 | 35 |
| +1 | 1.8 | 63 |
| +2 | 3.2 | 112 |
| +3 | 5.5 | 192 |
| +4 | 9 | 315 |
| +5 | 15 | 525 |
| +6 | 25 | 875 |
| +7 | 42 | 1,470 |
| +8 | 70 | 2,450 |

SELL에 놓으면 현재 단계의 판매가를 해당 라운드 판매액에 즉시 더하고 상품을 제거한다. 판매 취소와 재구매는 없다. 별도의 지갑 잔액은 없으며 화면의 금액은 현재 라운드 누적 판매액이다.

예를 들어 +3 한손검은 192다. 이 상태에서 다음 강화를 시도하면 성공 시 315, 하락 시 112, 파괴 시 0이 된다. 1라운드 판매액이 100이라면 현재 검을 팔아 292로 목표를 달성할 수 있으므로 추가 강화 없이 멈출 이유가 생긴다.

## 라운드와 목표액

`목표액(r) = RoundToInt(250 × 1.45^(r - 1))`

| 라운드 | 목표액 |
| --- | ---: |
| 1 | 250 |
| 2 | 362 |
| 3 | 526 |
| 4 | 762 |
| 5 | 1,105 |

반올림은 Unity의 `Mathf.RoundToInt`를 사용한다. 정확히 중간인 값은 짝수 쪽으로 반올림하므로 362.5는 362다. 계산에는 반올림된 이전 목표가 아닌 첫 목표와 라운드 지수를 사용한다.

다음 라운드 조건은 현재 판매액이 목표액 이상이고, 손과 작업대가 모두 비어 있는 것이다. 보관대가 가득 찼다면 남은 작업대 상품은 판매하거나 기존 보관품을 꺼내 판매해 자리를 만들어야 한다. 진행 버튼은 물건을 자동 판매하거나 보관하지 않는다.

| 데이터 | 다음 라운드 처리 |
| --- | --- |
| 라운드 번호 | 1 증가 |
| 판매액 | 0으로 초기화 |
| 시도 횟수 통계 | 0으로 초기화 |
| 공급 상품 | 남은 공급품을 정리하고 +0 상품 6개 생성 |
| 보관 상품 | 종류·단계·보관 칸 유지 |
| 손과 작업대 | 비어 있어야 진행 가능 |

## 보관과 실패

보관대는 6칸이다. 한 칸에는 상품 1개만 놓을 수 있고 자동 정렬이나 교환은 없다. 빈손으로 보관 상품을 클릭하면 다시 들 수 있다. 보관품을 작업대에 올려 추가 강화하거나 그대로 판매할 수 있다. 보관 자체는 목표 판매액에 기여하지 않는다.

공급, 손, 작업대, 보관대에 상품이 하나도 없고 판매액이 목표액보다 낮을 때 실패 상태가 된다. R을 누르면 같은 라운드와 목표액으로 재도전한다. 판매액과 시도 횟수는 0이 되고 공급품 6개를 다시 받는다. 이 시점에는 보관품도 남아 있지 않으므로 복구할 보관품은 없다.

목표 달성 후 상품이 모두 없어져도 실패가 아니다. NEXT ROUND로 진행한다. 상품이 보관대에만 남아 있다면 꺼내서 진행할 수 있으므로 실패로 판정하지 않는다.

## 화면 정보와 피드백

| 영역 | 표시 내용 |
| --- | --- |
| 좌측 상단 | 라운드, 현재 판매액/목표액, 누적 강화 시도, 횟수 무제한 표시 |
| 상단 중앙 | 강화 결과, 잘못된 행동 안내, 목표 달성 또는 실패 안내 |
| 좌측 하단 위 | 상품 위치, 이름, 단계, 현재 가치, 다음 시도 확률 |
| 좌측 하단 아래 | 시점·선택 입력과 좌우 공간 안내 |

상품 정보는 포인터가 가리킨 상품을 우선하고, 없으면 작업대 상품, 그다음 손의 상품을 표시한다. 보관된 고단계 상품도 클릭 전에 가치를 확인할 수 있어야 한다.

작업대가 비어 있음, 이미 상품을 들고 있음, 작업대가 차 있음, 보관 칸이 차 있음, 목표 미달, 최대 강화 단계와 같은 상황은 상태를 바꾸지 않고 안내한다. 실패 메시지는 임시 결과 메시지보다 우선한다.

## 진행 저장

상품 집기·배치·보관·판매, 강화 결과 확정, 라운드 전환, 실패 후 재도전 때 진행을 저장한다. 저장 대상은 라운드 번호, 판매액, 시도 횟수, 살아 있는 모든 상품의 종류·단계·위치·슬롯이다.

재실행 시 손에 들었던 상품과 작업대 상품도 복원한다. 강화 도중 종료하면 마지막으로 저장된 확정 상태에서 이어진다. 망치 애니메이션 도중의 시간과 시점 방향은 저장하지 않는다. 저장 초기화는 개발용 메뉴에서 제공한다.

## 초기 밸런스의 범위

기본 공급품을 모두 +0으로 팔면 220이므로 첫 목표 250을 달성하려면 일부 강화가 필요하다. 상품의 소모가 시도 횟수 제한을 대신하며, 고단계에서 파괴 가능성이 커져 판매와 보관의 의미가 커진다.

현재 수치는 짧은 프로토타입 검증용이다. 최대 강화 단계는 고정되어 있지만 목표액은 계속 증가하므로 장기 플레이에 그대로 적용하면 언젠가 달성할 수 없는 목표가 생긴다. 공급품 6개의 최대 판매 합계는 15,400이고, 동일 구성의 보관품까지 준비하면 해당 라운드에서 추가로 사용할 수 있다. 보관대는 임의 조합이므로 실제 상한은 보관품 구성에 따라 달라진다.

정식 진행을 설계할 때는 최종 라운드와 결말, 목표 증가 상한, 공급량 증가 또는 최대 강화 확장 중 적절한 방식을 결정해야 한다. 현재 프로토타입에는 최종 승리와 엔딩, 이동·전투, 상점, 제작, 오디오 연출, 강화 단계별 모델 변화가 포함되지 않는다.
